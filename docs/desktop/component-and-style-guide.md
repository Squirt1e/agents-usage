# 桌面面板组件与样式规范

本文从当前 macOS 菜单栏面板的实现中提炼可复用约定，供后续功能设计、组件开发和代码审查使用。
它描述的是桌面路径 `src/desktop/` 的界面系统，不替代功能规格：用户可观察行为仍以
[`openspec/`](../../openspec/) 为准，动效与颜色的强制规则仍以 [`AGENTS.md`](../../AGENTS.md)
及测试守卫为准。

## 1. 如何使用本文

- **实现事实**：组件职责、DOM 语义和现有视觉语言，以当前源码为依据。
- **新增约束**：后续功能应复用的组合方式，以及不应绕过的边界。
- **唯一真源**：颜色值、时长和窗口计算不抄到本文维护；分别以
  [`panel.css`](../../src/desktop/panel.css)、[`panel/panel-height.ts`](../../src/desktop/panel/panel-height.ts)
  和对应测试为准。本文只说明这些值的语义和选择方法。

只改文案或业务字段时，先寻找已有组件能否表达；只有现有组件无法承载新的交互语义时才新增组件。
不要为了页面局部效果复制一组样式。

## 2. 设计原则

### 2.1 紧凑，但不压缩语义

面板是固定 350 逻辑像素宽的菜单栏工具，不是缩小版网页。标题、数据与置信度留在卡片内；
连接错误在底部按需展开，恢复操作留在原有配置页。空间不足时让详情纵向滚动，不允许横向滚动。

### 2.2 平台之间隔离失败

一个平台或连接的失败不能替换其他平台的有效数据，也不能在卡片内追加错误框或按钮。
已有缓存继续显示并明确标记“数据已过期”；连接状态在底部详情浮层按平台和连接分列。
新数据源应先在数据层形成明确的连接状态，再进入展示组件。

浮层里每一条都必须归属到它真正所属的连接：服务的连接身份写在 `connections` 里，state 级与
快照级的 `connection` 要等该连接成功过一次才有。面板统一用 `stateConnection()`
（`src/shared/desktop-contract.ts`）解析身份，卡片与浮层共用同一个结果：一条从未成功过的实验
连接（开关关闭、或还没粘贴凭据）在浮层里显示它自己的名字（`网页用量`、`钱包`），开关关闭时
既不计入「连接异常」，也不出现在浮层里。

### 2.3 视觉角色与业务品牌分离

- `--action` 表示可操作、焦点或选中。
- `--switch-bg`、`--switch-thumb` 表示开关关闭：状态由轨道承担，旋钮在关闭与开启两态都是同一个
  白色滑块，`--switch-thumb-shadow` 只负责在浅色主题里给白色旋钮补出边界。
- `--switch-on-*` 表示开关已启用；禁用不另设颜色，走面板统一的淡化。
- `--mint`、`--lime`、`--indigo` 表示平台、额度和数据身份。
- `--warning`、`--danger`、`--estimate` 表示状态或数据置信度；`--low-value-warning` 用于低额度和低余额读数。

浅色主题中这些角色必须保持可区分；不要用平台色代替系统操作色，也不要用“警告色”装饰普通信息。

### 2.4 每个可见切换都要有运动

页面、显隐、选中、悬停、状态、数值和尺寸变化都必须遵守 [`AGENTS.md`](../../AGENTS.md) §1。
同一元素换状态用 `transition`，挂载后的入场用 `animation`，宿主窗口尺寸和 SVG 路径这类 CSS
无法插值的对象才允许逐帧驱动。任何新切换必须登记到
[`panel-motion.test.ts`](../../tests/panel/panel-motion.test.ts)。

## 3. 窗口与布局骨架

两个宿主窗口，两套骨架，共用同一套 Token 与控件。

```text
面板窗口（index.html，350 × 内容高）        设置窗口（settings.html，600 × 400 固定）
PanelApp                                  SettingsApp
└── Panel                                 └── SettingsPanel
    ├── panel-header  标题 / 工具栏             ├── settings-nav    分类纵排，不滚动
    ├── panel-body    唯一纵向滚动区域          │    平台管理 / 外观 / Codex / GLM / DeepSeek
    │   └── OverviewView  平台卡片列表          └── settings-content  唯一纵向滚动区域
    ├── panel-bottom                                  └── settings-pane  当前分类
    │   ├── panel-footer  固定的同步状态                    ├── AppSettings    平台管理 / 外观
    │   └── PanelToasts   脱离文档流的消息栈                └── ProviderSettings  单平台配置
    └── ConnectionDetails  底部详情层（无布局占位）
```

布局约束：

- `PanelApp` 持有面板的数据与副作用，`useSettingsWindow`（`settings/settings-window.ts`）持有设置窗口的
  数据与副作用；纯展示组件不自行请求数据或持久化设置。两个窗口各持一个 `settings-store` 实例。
- 面板只有一个页面（总览），因此没有换页动效、没有返回入口、工具栏不会隐藏。`.panel` 是固定宽度、
  全高的纵向 flex 容器，`.panel-body` 是唯一可滚动内容区。
- 面板窗口高度 = 框架 + 总览内容实际高度，上限由宿主的 `clamp_panel_height` 按当前显示器的工作区
  决定；CSS 侧只保留 `max-height: 100vh` 作为上限。**没有最小高度**，也不再按卡片张数取整：
  空总览就是一块矮面板。高度由 `usePanelHeight` 测量并逐帧上报，且必须保留重算路径（安全 tick 与
  `visibilitychange`），理由见 `panel/panel-height.ts` 的模块头注释。
- 设置窗口尺寸固定，内容区滚动，分类导航不滚动。`.settings-content` 是唯一滚动区；窗口本身
  不可缩放，`min_inner_size` 与 `max_inner_size` 都等于目标尺寸。
- 两个窗口的内容都只能向下增长。子元素必须允许收缩，并对长单词、URL 和错误信息使用断行；不得通过
  增加宽度或横向滚动解决溢出。
- 面板卡片不再带 `data-panel-block` 标记（高度改为量内容元素的完整高度）；设置分组也不参与计算。
- `.panel-body` 四边内边距统一为 10px，由内容容器负责卡片到窗口边缘的留白；相邻卡片不使用
  `.overview` 的 `gap`，而由 `.provider-card:not(:first-child)` 的 10px 上外边距分隔。
  `.panel-bottom` 自身不增加上间距，也不使用负外边距抵消正文内边距。
- 页脚和 toast 不进入卡片高度预算；toast 以 `.panel-bottom` 为锚点浮在正文上方，不能推动内容。
  底部浮层所在的层叠上下文高于卡片内的重置时间、低于阻断式对话层；连接详情使用不透明表面，
  避免长错误信息与卡片读数叠字。
  标题栏隐藏时整个 `.panel-bottom` 同步淡出并退出 flex 布局，宿主沿既有高度动画收紧窗口。

## 4. 样式 Token

### 4.1 颜色

所有颜色必须来自 CSS 变量。深色与浅色主题必须定义相同的一组颜色变量，普通规则中禁止出现
十六进制、`rgb()` 或 `rgba()` 字面量。完整值以 [`panel.css`](../../src/desktop/panel.css) 顶部的
两个主题块为准。

| Token 组 | 用途 | 使用规则 |
| --- | --- | --- |
| `--tile*`、`--card*`、`--control-bg` | 面板、卡片与控件表面 | 按容器层级选择，不临时混入透明白或透明黑 |
| `--line*`、`--*-border` | 分隔、描边和状态边界 | 普通边界与状态边界分开，状态色只用于对应状态 |
| `--text`、`--text-dim`、`--text-faint` | 主信息、辅助信息、弱提示 | 不用 opacity 临时制造新的文字层级 |
| `--action`、`--active-*` | 操作、焦点、选中 | 不承担平台身份或健康状态 |
| `--switch-*`（含 `--switch-thumb-shadow`）、`--switch-on-*` | 开关关闭与开启 | 状态由轨道表达，旋钮两态都是同一个白色滑块；与选中按钮的 `--active-*` 分开 |
| `--mint`、`--lime`、`--indigo`、`--ring-*` | 平台和额度识别 | Codex / GLM / DeepSeek 保持既有映射 |
| `--warning*`、`--danger*`、`--estimate*`、`--low-value-warning` | 警告、错误、估算、低值提醒 | 额度只改变填充与百分比数字，余额只改变金额；错误色不用于普通强调 |
| `--cover-*`、`--toast-*`、`--overlay-*` | 覆盖层和浮层 | 只用于对应层级，避免随意创建新的半透明层 |

新增颜色角色时，必须同时补齐两套主题并明确语义；若只是已有角色的另一处使用，直接复用现有变量。

### 4.2 字体与数字

- 正文使用 macOS 系统字体栈；**字号只能取命名档位**，规则里不写裸像素：
  `--text-2xs` 10（极次要提示、标记）→ `--text-xs` 11（控件、状态行、核心标签）→
  `--text-sm` 11.5（区块标题、输入框）→ `--text-md` 12.5（卡片名、指标值）→
  `--text-base` 13（设置窗口文档基准）→ `--text-lg` 13.5（面板窗口标题）→
  `--text-xl` 15（设置窗口 pane 标题）→ `--text-display` 19（总览大号数字）。
  相邻档位至少差 0.5px，否则不成其为层级；由
  [`panel-type-scale.test.ts`](../../tests/panel/panel-type-scale.test.ts) 守住，新增字号必须落进档位。
- 文档基准字号用 longhand 声明而不是 `font` 简写：简写里只要有一个部件是 `var()`，
  token 不合法时整条声明都会失效并退回继承值。
- 平台名、区块标题使用半粗体，不新增大号“宣传型”标题。
- 额度、余额、倒计时和时间使用 `--mono`，并启用 `tabular-nums`，防止实时更新引发布局跳动。
- 数值旁的 `%`、单位、置信度标签应降级呈现，不能与主数值争夺层级。
- 金额、Tokens、日期和百分比统一通过现有格式化函数输出，不在组件里拼接未经归一化的业务值。

### 4.3 间距、圆角和尺寸

当前界面使用紧凑的 1–14px 间距范围：页面卡片间距略大于卡片内部模块间距，模块间距略大于
标签内部间距。新增界面应优先从现有的 `4 / 5 / 6 / 7 / 8 / 9 / 10 / 12px` 组合中选择，
不要引入只服务于一个元素的间距刻度。

- 面板宽度：350px；宿主和 CSS 必须同步。
- 面板最小高度：320px；高度由 [`panel/panel-height.ts`](../../src/desktop/panel/panel-height.ts) 计算。
- 通用区块圆角：`--radius`；按钮和输入框 8px；胶囊、开关和状态标签使用全圆角。
- 交互热区不能等同于细小图形本身。额度环/条的整个条目都是点击区域，图标按钮使用固定方形热区。
  只有文字可点的入口（`.link-button`）与只有图标可点的把手（`.drag-handle`）用**伪元素**扩热区
  （`inset` 负值），不引入 padding——padding 会把所在行撑高，改变一整个表单的节奏。
- 设置窗口的滚动条跟随系统（覆盖式、滚动时出现）：面板隐藏滚动条的规则被限定在面板文档
  （`:root:has(#panel-root)`），因为设置窗口的分区确实会溢出。

## 5. 组件分层与使用规范

### 5.1 外壳与导航

| 组件 | 职责 | 后续使用约束 |
| --- | --- | --- |
| `PanelApp` | 聚合快照、设置、刷新、toast，并把每个设置入口转成一次开窗请求 | 业务副作用留在此层或专用 hook，不下沉到纯展示组件；面板不新增页面 |
| `Panel` | 标题、工具栏、滚动正文、页脚和详情插槽 | 面板只有一页，因此没有 `viewKey` / `direction`；新增设置界面属于设置窗口，不属于这里 |
| `SettingsPanel` | 设置窗口的分类导航与内容区 | 分类一次只挂载一个；分类身份即 pane 的 React key，靠它重放内容入场动效 |
| `PanelIconButton` | 统一顶部图标按钮、按下态和无障碍名称 | 图标按钮必须提供 `label`；可切换动作使用 `pressed`，临时工作态使用 `disabled` |
| `PanelToasts` | 展示动作完成后的短暂消息 | 只报告已经发生的结果；不承载确认、输入或必须长期保留的信息 |

设置窗口的分类导航是竖直 tablist，方向键在同一控件内移动（roving focus），不是一组独立按钮；
窗口没有返回入口——关掉它就是返回，Escape 由宿主规则处理。面板工具栏常驻，不再有需要淡出的状态。

### 5.2 内容容器

| 组件 / 类 | 职责 | 后续使用约束 |
| --- | --- | --- |
| `OverviewView` / `.overview` | 按持久化顺序组合平台卡片 | 不在此处混入平台选择器；全隐藏时使用 `EmptySelectionState` |
| `PlatformCard` / `.provider-card` | 平台身份、计划、高峰状态、设置入口和内容槽 | 卡片本身不解释指标；平台专属数据组合留在 `*Card` 组件 |
| `CardSection` / `.card-section` | 统一卡片内“主指标 → 辅助指标”层级 | 主指标不重复标题；辅助指标保留语义名称和细分隔线，并以安全位移动画进入，仅在分组名本身承载信息时显示标题（如“钱包”） |
| `.provider-body` | 承载卡片的语义分组 | 不直接堆叠业务指标；由 `CardSection` 统一控制分组节奏 |
| `.config-block` | 设置页的语义分组 | 一个区块只承载一个设置主题；标题用 `h3`，说明紧随相关控件 |
| `.peak-window-card` | 自定义高峰时段里的一条时段 | 两行回答两个问题（哪几天 / 几点到几点）；删除入口与它删除的那一行同层，跨天标记也留在本行 |
| `.overlay` + `.dialog` | 需要暂时阻断底层操作的管理任务 | overlay 高于 toast；普通设置页不要做成弹层 |

新平台卡片应复用 `PlatformCard`，并在共享契约中先建立平台身份。不要复制卡片 header，也不要通过
CSS 选择器伪造一个未进入 `ProviderId` 的平台。

结构化列表编辑器（目前只有高峰时段）遵守三条约定。**宽度是第一约束**：设置内容区给这类区块只有
366 像素，所以一行只回答一个问题，标签写成值前面的弱化前缀（`开始 09:00 → 结束 18:00`）而不是
另起一行的标题——把星期、两个时间框和删除按钮挤进同一行的结果，就是原来那条读不出起止的窄带。
**反馈就地发生**：影响这一行的规则（跨天、非法）出现在这一行上，判定结果（此刻高峰还是错峰）
出现在列表下方，都不放到区块末尾的说明行里。**出口也是状态**：删除先播过渡再改数据，与消息栈
同一套 `is-leaving`；也正因为退出状态活在组件里，行必须用稳定 key——用下标会把退出状态交给补位
上来的那一行（见 `PeakDraftRow`）。

平台存在生效的高峰时段定义时，`PlatformCard` 可以接收当前时段状态，但只有 `peak` 显示头部状态胶囊
和卡片内侧的短强调线；不改变整卡描边、不增加外发光。`offpeak` 与普通卡片视觉一致且不暴露标签。跨边界 toast 属于独立的通知行为，
不由卡片标签是否可见决定。

平台卡片本身不是入口，因此不响应整体 hover，也不使用浮起阴影暗示可点击；悬停、按下和焦点反馈只属于
齿轮、额度图形、重置时间等真实交互区。高峰也不借用阴影制造告警感，这两条由
`tests/panel/panel-card-shadow.test.ts` 守住。

### 5.3 数据展示

| 组件 | 适用内容 | 不适用内容 |
| --- | --- | --- |
| `QuotaDisplay` | 有明确窗口、百分比和重置语义的额度 | 余额、累计 Tokens、没有上限的计数 |
| `MetricRow` | 一行标签与一个主值，可附置信度和过期标记 | 需要多步操作的表单或长错误信息 |
| `ConfidenceTag` | “估算”“实验数据源”等来源置信度 | 连接健康状态 |
| `StaleTag` | 缓存仍可展示但已经过期 | 无数据或请求中的占位 |
| `StatusRow` | 配置页中的连接状态与附加说明 | 总览卡片内的错误块 |
| `ConnectionDetails` | 底部按需展开的只读连接错误详情 | 占用卡片布局或提供重复的恢复入口 |

额度环与进度条是同一份数据、同一条 SVG 描边的两种形态，只能通过 `QuotaDisplay` 切换。
不要分别实现“圆环组件”和“进度条组件”，否则几何、状态和无障碍语义会分叉。重置时间行只在自身
具有“倒计时 / 绝对时间”切换时截获点击，其余区域继续属于形态切换热区。

额度数值模式是“外观”里的全局设置，由 Codex 与 GLM 共同使用并只持久化一次，默认选择“剩余”。
`QuotaDisplay` 的描边、数值和无障碍名称必须使用同一方向；数据源没有返回所选方向时显示缺失，
不用另一方向推算。额度区不再常驻显示口径或点击说明；图形与重置时间继续通过各自的无障碍名称、
完整热区和 hover/active/focus 反馈表达操作，不增加重复按钮。

低额度提醒同样是“外观”里的全局设置，取 0–100 整数，默认 10；0 明确表示关闭。它与显示方向
分离：`QuotaDisplayItem.percent` 只负责当前数字和描边长度，`remainingPercent` 专门负责提醒判断。
卡片优先使用来源明确的剩余读数，只有它缺失时才以 `100 - 已用` 换算；两者都不可用就不猜测。
命中边界（剩余量小于或等于提醒值）时，形状填充、圆环数字、进度条数字与刷新重放数字统一使用
`--low-value-warning`，无障碍名称追加“低额度提醒”，标签、轨道和重置时间保持原层级。显示百分比为 0
或未知时，填充 path 必须使用 `butt` 线帽，避免零长度描边的圆角端点产生亮点；这个修正不受提醒
是否关闭影响。进入和离开提醒的颜色变化使用 150ms 反馈过渡，并由 reduced-motion 兜底关闭。

低余额提醒也是“外观”里的全局设置，接受非负数字，默认 10；0 表示关闭。GLM 钱包与 DeepSeek
对每条真实余额使用来源返回的原始金额独立判断，不合计币种也不换算汇率；余额小于或等于提醒值时，
只有 `.metric-value` 使用 `--low-value-warning`，并在该行无障碍名称中追加“低余额提醒”。缓存余额继续
判断，占位金额、缺失值与无法解析值不提醒；消费、Tokens、币种标签和卡片层级均不受影响。

Codex 与 GLM 的已知窗口使用同一套紧凑词汇：五小时为“5小时”，每周为“7天”，GLM 月度工具窗口为
“月度”。成功刷新后的数字从 0 重播只发生一次；圆环与进度条互换时只播放几何形变，数字始终使用当前
静态读数，不把形态切换误当成第二次刷新。

数值展示遵循以下优先级：

1. 有效、范围匹配的权威值；
2. 明确标记来源的实验值或估算值；
3. 可继续使用的缓存值，并附 `StaleTag`；
4. 无可靠值时隐藏该指标或显示对应状态，绝不把缺失值写成 `0`。

DeepSeek 是更严格的特例：余额始终按稳定钱包连接展示；今日消费、Tokens 和请求次数只属于用户
显式启用并配置 Token 的网页用量连接，并统一放在无可见标题的“今日用量”辅助分组。连接关闭时这些行完全不存在；启用但未配置 Token 时显示
一块 `FrostedHint` 占位，由 `CardSection` 的细分隔线与余额区分，不绘制嵌套卡片的完整边框和底色；不得用余额差分
估算填充今日消费，也不得在主卡放置“前往配置”状态块。

余额模块是**平台自己给出的官方读数**（API Key 的答案），因此和 GLM 的模块一样**永远保留正式
排版**：没有可展示的读数时留下占位金额并盖上遮蔽提示（服务报缺少配置 → 「配置 API Key 后显示
余额」，其他失败 → 「暂无余额数据」），而不是让整张卡片塌成只剩标题、用户无处可点。覆盖容器是
`.card-module`（`position: relative`，`gap` 与 `.card-section-content` 相同，自身不画底色），这样把
原本直接挂在卡片上的行包起来不会改变任何间距。失败时提示只写中性说明，不引用服务原始错误。

GLM 钱包与 DeepSeek 网页用量遵循**同一套实验连接交互：一个开关**。开关同时决定采集与展示——
打开即在卡片上出现该模块（有数据展示数据；尚未配置凭据时保留正式排版并盖上「配置…后显示用量」的
遮蔽提示，不使用户失去配置入口），关闭即停止采集并让模块整块消失、不在总览与底部连接状态留下
痕迹。**关闭不删除凭据**：撤销凭据只能由凭据表单里的「删除」按钮完成，开关的说明文案不得承诺
「关闭即删除」。总览在 `OverviewView` 里按 `switchedOffConnection()` 把关闭的连接整条从视图里
摘掉（GLM 钱包与 DeepSeek 网页用量同一处规则），卡片自身再按 `walletEnabled` / `webEnabled`
兜一层——连接身份还可能只写在 metrics 级、state 级摘不干净，两层都在才算「不留痕迹」，关闭前
采集到的余额也才不会留在卡片上冒充实时读数。

三张卡片的内部结构统一为“平台头部 → 主要指标 → 辅助分组”：Codex 和 GLM 的额度是主要指标，
DeepSeek 的余额是主要指标；Codex Tokens 与 DeepSeek 的消费、Tokens、请求进入“今日用量”，GLM 钱包
进入“钱包”。卡片内不额外创建状态区，连接错误仍只走底部详情或设置页。

### 5.4 空态、加载与覆盖

| 组件 | 使用时机 |
| --- | --- |
| `LoadingState` | 首次读取且尚无任何可展示快照 |
| `ServiceUnavailableState` | 本地服务整体不可达，所有平台都无法读取 |
| `EmptySelectionState` | 所有平台都被隐藏 |
| `MissingWindowNote` | 供应方缺少一个有独立语义的额度窗口 |
| `FrostedHint` | 需要保留正式布局轮廓、但必须遮住占位数据的模块 |

`FrostedHint` 是安全边界，不是装饰：容器必须在显示占位数据时添加 `.is-covered`，显示任何真实数据
（包括缓存）时移除。遮挡必须由 `.is-covered > :not(.frost-hint)` 上的普通 `filter` 完成，不能依赖
`backdrop-filter`；cover 和文字首帧必须完整，不得增加透明度入场。毛玻璃区域用原生按钮承接点击与键盘
操作，打开本平台设置；不添加跳转图标、链接文案、手型鼠标或悬停态。未配置时只显示一行具体的
“配置后显示什么”说明，不在卡片上重复“需要配置”；其他失败时只写“暂无数据”，完整错误在底部
详情与设置页查看。

### 5.5 表单与操作控件

| 模式 | 组件 / 类 | 选择标准 |
| --- | --- | --- |
| 主操作 | `.primary-button` | 当前区块唯一的提交或确认动作 |
| 次操作 | `.ghost-button` | 重试、前往配置等不会与主操作竞争的动作 |
| 轻量链接动作 | `.link-button` | 删除凭据、添加一行等上下文明确的低视觉重量动作 |
| 文本输入 | `.text-input` | Key、路径、时区和时间等直接编辑 |
| 单选分段 | `SegmentedGroup` + `.segmented-option` | 2–3 个短标签且所有选项需要同时可见；共用滑块跟随选中项移动 |
| 布尔开关 | `.switch` | 独立、即时生效的开/关状态；关闭由轨道表达（旋钮不得用禁用灰），禁用整块淡化 |
| 破坏性动作 | `.danger-button` | 只有「确认删除凭据」这类不可撤销的动作；用 danger 表面承载语义，不用操作色假装成普通按钮 |
| 就地确认 | `.credential-confirm` | 破坏性动作的两步确认：第一次点击只展开确认并说明后果，焦点落在安全动作上，Escape 与取消都回退焦点 |
| 设置行 | `.setting-row` | 左侧名称/说明，右侧单一控件 |

按钮文案保持单行。横向空间不足时让输入框收缩或让复杂编辑器换行，不压缩按钮热区。开关使用原生
checkbox 语义；开关只在自己的写入进行中整体淡化（`opacity`），无关的设置写入（主题、额度数值、
其它平台、排序）不改变它的可用性，因此关闭态永远读作“可以打开”，而禁用态读作
“暂时点不动”；分段选项使用 `aria-pressed`；进行中的写操作必须禁用重复提交并提供状态反馈。

**禁用态分两档，判据是这个禁用会持续多久**（见
[`polish-settings-window`](../../openspec/changes/archive/2026-09-16-polish-settings-window/design.md)）：

| | 例子 | 画法 |
| --- | --- | --- |
| 持续不可用 | 空输入的提交、没有改动可保存的保存入口 | `--disabled-bg/-border/-text` 表面，标签保持 ≥4.5:1 可读 |
| 写入期间的短暂禁用 | 分段控件、开关、保存中的输入框 | 保留原有的整体淡化：它表示「这次点击已收到」，读作「不可用」是错的 |

持续不可用**不得**用整体 `opacity`：主按钮在白底浅色主题下会退到 2.5:1，用户读不出它要做什么。
`.link-button` 与 `.text-input` 也必须有可辨的禁用态——它们一度与启用态完全相同（同色、
同 `cursor: pointer`），因为作者规则里的 `color` 盖掉了 UA 的灰化。
主题、全局额度数值、服务区域与时段来源共用一个随选中项位置和宽度滑动的高亮块；星期多选
允许同时选中多个按钮，仍使用各自的高亮，不挂载滑块。滑动单选在保存期间可阻止重复点击，
但文字不变暗，也不在悬停时额外提亮；减弱动效时滑块直接落到目标位置。
低额度提醒使用带 `%` 后缀的数字输入，低余额提醒使用无币种后缀的非负数字输入：本地草稿只在失焦或
Enter 时确认，非法值留在原处说明且不发送写入，保存失败恢复上一个合法值；两者各自保存，写入期间
只禁用当前输入，不影响另一项提醒、主题与额度数值控件。

凭据表单的状态行始终是**一行**：左边「已保存 ····掩码」或「尚未配置」，右边删除入口。保存成功后
不追加成功文案——掩码本身就是确认（规格：成功清空输入并仅返回掩码状态），多出来的整行会把删除
按钮挤到状态行下方，同一个表单在静止态与刚保存后长得不一样。失败原因、删除告知这类必须说出口的
文字独占状态行**下方**一整行（`.credential-feedback` 的 `flex: 1 1 100%`），因此标记里它必须写在
删除按钮之后：flex 行按 DOM 顺序断行，写在它后面的按钮会掉到下一行。

凭据保存成功后立即触发一次该平台的采集，打开实验连接开关（GLM 钱包 / DeepSeek 网页用量）同理。
否则用户刚配好凭据、切回总览看到的仍是一张空卡或旧读数，读起来像密钥填错了。

**凭据是展示闸门的一部分，不只是采集闸门。** 服务在凭据被删除后仍会继续发布上次落库的快照，所以
每个模块都要把「该连接的凭据是否已保存」纳入判断：没有凭据就回到模板 + 遮蔽提示（GLM 额度、
GLM 钱包、DeepSeek 余额、DeepSeek 网页用量一致），有凭据但采集失败才显示缓存值并标记过期。
只读视图会让用户删掉密钥后看到余额/额度原样挂着，像是仍然有效。删除凭据后同样要再采集一次：卡片
已由闸门回到模板，但设置页那条连接状态行否则还在用一把不存在的密钥声称「数据正常」。

**改变「采集什么」的设置写入后立即重采。** 目前是：服务区域（换端点）、Codex CLI 路径（换采集
进程）、打开实验连接开关。其余设置写入都是呈现层的（主题、额度数值、低额度提醒、低余额提醒、重置时间格式、平台显隐与
顺序、高峰时段），不触发采集；凭据的保存与删除另按上面两条处理。

## 6. 状态和文案语义

连接状态统一由 [`components/StatusRow.tsx`](../../src/desktop/components/StatusRow.tsx) 映射，不在页面内另造同义词。
**一个连接只在一个地方说明自己**：状态行在区块正文里、位置固定——不受开关控制的连接是正文第一行，
由开关控制的连接紧跟开关之后（放在开关之前会被读成「这个开关当前无效」）。不允许再在标题旁用第二种
标记复述同一件事（曾经存在过一枚胶囊，已删除）。失败时状态行必须带上出路——默认建议表在同一个文件里
（`recoveryAdvice`），连接可以覆盖为自己的说法，但**每一种失败类型都要有一句**，包括首次使用时最常见
的「需要配置」；由 [`status-vocabulary.test.ts`](../../tests/shared/status-vocabulary.test.ts) 遍历所有类型守住。

| 语义 | 标准文案 | tone |
| --- | --- | --- |
| 正常 | 数据正常 | `healthy` |
| 未连接 / 缺配置 | 尚未连接 / 需要配置（仅设置页） | `neutral` |
| 限流 / 网络 / 过期 | 请求受限 / 网络异常 / 数据已过期 | `warning` |
| 认证 / 兼容 / 进程 / 存储错误 | 认证失败 / 接口不兼容 / 采集进程异常 / 存储异常 | `danger` |
| 未知 | 状态未知 | `neutral` |

文案规则：

- 先说当前事实，再给恢复入口；不要用颜色替代文字说明。
- 设置页说明只写配置方法、操作后果和必要的数据源限制，不暴露 Keychain 内部账号标识。
- 未验证的数据必须明确写“估算”“实验数据源”或“部分数据”。
- 长错误信息仅在底部详情或设置页断行展示，不能进入总览卡片。
- 总览卡片不追加连接错误状态块、原始错误或恢复按钮；原有配置图标与无数据遮蔽提示保留。
- toast 使用简短结果句，不重复底部详情中的原始错误。

底部同步摘要只概括**当前可见平台**，并采取保守口径：没有可见平台时显示“未展示平台”；任一可见平台
尚无成功时间时显示“部分平台尚未同步”，且不点亮绿点；只有全部可见平台都有成功时间时，才显示其中
最早的时间为“全部同步于 HH:mm”并点亮绿点。这样摘要表达的是整屏数据共同达到的下限，不用最新的一张
卡片替其余卡片背书。

## 7. 交互、动效与焦点

### 7.1 动效预算

- 颜色、边框、背景、透明度：150ms `ease`。
- 位移和入场：160–180ms，使用既有缓动曲线或 `ease-out`。
- 数值与尺寸：200–260ms `ease`。
- 面板整体显隐：260ms，必须短于宿主隐藏窗口的等待。
- 循环动画只用于持续中的状态；减弱动效时必须停止。

禁止 `transition: all`，禁止对参与窗口高度测量的 `height`、`scale` 等布局结果做动画。页面入场只
使用 opacity 和 translate；拖动行的 transform 由指针逐帧控制，不能添加 transition。

已登记的例外只有以下几类，新增功能不能顺手扩大例外范围：主题渐变无法直接插值；拖动位移必须
逐帧跟随指针；焦点环必须立即出现；纯文本替换没有可插值属性；遮挡占位数据的 cover 必须首帧
完整。额度路径和宿主窗口高度不是“无动效”，而是由脚本逐帧驱动。

### 7.2 减弱动效

CSS 动效由文件末尾的 `prefers-reduced-motion` 全局兜底关闭。窗口高度和额度形态这两个逐帧动效
必须在 TypeScript 中检查同一偏好，并直接绘制目标状态。新增 JS 补间需要先证明 CSS 无法表达，
同时补充相应测试。

### 7.3 焦点与无障碍

- 所有仅图标按钮都要有准确的 `aria-label`。
- 持续中的图标操作要同时提供可见忙碌反馈和 `aria-busy`；刷新全部平台时按钮禁用防重入、图标循环旋转，
  所有可见平台的请求结束后恢复，减弱动效下由统一兜底停止旋转。
- 可切换按钮通过 `aria-pressed` 暴露状态，不能只依赖颜色或图形。
- 键盘焦点环必须立即出现，不参与动效。
- 页面返回后应把焦点恢复到打开该页的入口；新增子页也应保留同样的往返关系。
- 拖动排序目前只有指针一条路径（原本还有一个方向键入口，已按要求移除）。新增任何只能拖动完成的操作前，先想清楚键盘用户怎么办——这条约束是上一版删掉的，不是不存在。
- `role="status"` 用于非阻断状态，`role="alert"` 只用于需要立即注意的错误。
- 面板表面默认不可选择文本，输入框和文本域必须恢复文本选择能力。

## 8. CSS 与组件实现约束

新增样式时按以下顺序判断：

1. 能否直接复用现有组件或状态修饰类；
2. 能否给现有组件增加一个有明确语义的 prop / data attribute；
3. 是否确实出现了新的可复用视觉角色，才新增 class 或 Token。

实现时遵守：

- 基础 class 定义结构和默认状态，`.is-*`、`[data-*]` 或伪类只描述状态差异。
- 业务身份使用 `data-provider`、`data-period` 等可读属性，不靠 DOM 顺序；唯一例外是目前第二个额度
  描边的既有 `:nth-child(2)` 映射，新增列表不应延续这种做法。
- 注释解释取舍和踩坑原因，不复述声明本身。
- 不把测试定位属性当作样式选择器。
- 不动画会影响高度测量的盒模型属性；必须变化时，让布局先得到明确终态，再使用不污染测量的
  opacity / translate 表达过程。
- 层级按既有约定：正文与 cover < 拖动行 < toast < overlay。新增浮层前先确认它属于哪一层。
